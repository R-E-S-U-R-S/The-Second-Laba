# StreamStats — лабораторная работа № 2

Пакет `streamstats` потоково анализирует события в CSV и JSONL, проверяет записи и сохраняет статистику в JSON.

## Требования

- Python 3.10 или новее.
- Для разработки: `pytest` и `ruff`.

## Установка

Из каталога проекта создай виртуальное окружение:

```bash
python -m venv .venv
```

### Windows

```powershell
.venv\Scripts\activate
```

### macOS / Linux

```bash
source .venv/bin/activate
```

Установи пакет и инструменты разработки:

```bash
python -m pip install -e '.[dev]'
```

## Запуск

### Просмотр справки

```bash
python -m streamstats --help
```

### Анализ CSV-файла

```bash
python -m streamstats analyze events.csv --format csv --output report.json
```

### Анализ нескольких JSONL-файлов

```bash
python -m streamstats analyze first.jsonl second.jsonl --format jsonl --output report.json
```

### Пропуск некорректных записей

```bash
python -m streamstats analyze events.jsonl --format jsonl --skip-invalid
```

По умолчанию параметр `--output` равен `report.json`.

При обнаружении некорректной записи обычный режим завершает CLI с кодом `2` и сообщает имя файла и номер строки.

С параметром `--skip-invalid` некорректные записи пропускаются. Для каждой такой записи выводится сообщение уровня `WARNING`, а их общее количество сохраняется в поле `skipped_invalid` отчёта.

Ошибки открытия или чтения файлов также приводят к завершению с кодом `2`.

## Модель события

Каждая запись должна содержать следующие поля:

| Поле | Описание |
|---|---|
| `timestamp` | Дата и время в формате ISO 8601 со смещением часового пояса |
| `level` | Уровень события: `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL` |
| `source` | Непустая строка — источник события |
| `message` | Строка с сообщением |

Пример значения `timestamp`:

```text
2026-10-07T12:00:00+03:00
```

### Форматы входных файлов

- **CSV** — файл должен содержать заголовки с именами полей `timestamp`, `level`, `source` и `message`.
- **JSONL** — каждая строка должна содержать один JSON-объект.

## Формат отчёта

Отчёт сохраняется в формате JSON и включает следующие поля:

- `total_events` — общее количество обработанных событий;
- `by_level` — количество событий по уровням;
- `by_source` — количество событий по источникам;
- `top_error_sources` — до пяти источников с наибольшим количеством событий уровней `ERROR` и `CRITICAL`;
- `first_timestamp` — время самого раннего события;
- `last_timestamp` — время самого позднего события;
- `skipped_invalid` — количество пропущенных некорректных записей.

### Правила формирования статистики

- В `top_error_sources` учитываются только события уровней `ERROR` и `CRITICAL`.
- При одинаковом количестве ошибок источники сортируются по имени.
- Для пустого набора событий временные границы равны `null`.

Элементы `top_error_sources` имеют следующий формат:

```json
{
  "source": "имя_источника",
  "count": 10
}
```
